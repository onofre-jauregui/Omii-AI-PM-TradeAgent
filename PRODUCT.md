# Product

## Register

product

## Users

Individual retail traders and sophisticated operators who run autonomous AI agents on Kalshi prediction markets. Primary user is the account owner-operator — someone technical enough to connect API keys and interpret P&L, but not necessarily a quant. They check the dashboard from their phone during the day; configure strategies and review compliance on desktop.

## Product Purpose

An AI-powered prediction market trading SaaS that lets users deploy autonomous strategies on Kalshi. The agent qualifies signals, sizes positions, manages risk, and learns from outcomes — all without user intervention. Success looks like a growing track record of profitable paper trades that earns trust for live capital deployment.

## Brand Personality

Terminal-native. Precise. Trustworthy.

The product handles real money. Confidence comes from clarity, not decoration. Think Bloomberg terminal meets modern SaaS — dense with signal, zero noise. Every interaction should reinforce that this is serious infrastructure, not a gamified fintech toy.

## Anti-references

- Robinhood / Coinbase Wallet: confetti, gamified streaks, round numbers, dopamine loops
- Generic SaaS cream/sand backgrounds with gradient hero blobs
- Bright gradient text, neon glassmorphism "AI aesthetic"
- Any interface that makes risk feel fun or downplays it

## Design Principles

1. **Signal over chrome** — Every pixel either carries data or creates structure. Decoration that doesn't inform is noise.
2. **Risk visible, not buried** — Live mode vs paper mode must be unmistakable at a glance. HITL pending approvals are P0 UI, not a footnote.
3. **Expert confidence** — Respect that the user knows what they're doing. No hand-holding copy, no excessive confirmations for read-only actions. Reserve friction for destructive or irreversible actions (live trades, key deletion).
4. **Density with legibility** — Dashboards need to pack information. Achieve this through tight spacing and good type hierarchy, not tiny fonts or collapsed cards.
5. **Dark-native** — The primary experience is dark mode. Light mode is a fallback, not the default.

## Accessibility & Inclusion

WCAG AA minimum. All interactive elements keyboard-navigable. Colorblind-safe: profit/loss distinction must be readable without relying on green/red alone (use +/- prefix and directional arrows). Reduced-motion respected on all animations.
